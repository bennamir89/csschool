Concept 1

What is DNS?

DNS stands for Domain Name System.

It looks up a human-readable domain name and returns the IP address associated with it.

Domain name

www.example.com

Easy for people to remember.

IP address

93.184.216.34

A numerical address used to identify a device/server on an IP network.

Think of DNS like a contacts list: you search for a name and retrieve the number/address linked to it.
DNS = name-to-address lookup04

How does a DNS lookup work?

The browser needs an IP address before it can contact the correct web server.

Note: DNS answers may be cached (temporarily stored), so the resolver may already know the IP address and not need to repeat the full lookup.

Concept 2

What is HTTP?

HTTP stands for Hypertext Transfer Protocol.

It is a set of rules that allows a web browser (client) and a web server to exchange requests and responses.

HTTP request

Sent by the client to ask for a resource, such as a web page or image.

HTTP response

Sent by the server with a status code and, when appropriate, the requested content.

HTTP is an application-layer protocol. It defines the format and meaning of messages exchanged between client and server.
HTTP = request and response rules06

Example request
GET /index.html HTTP/1.1
Host: www.example.com
Example response
HTTP/1.1 200 OK
Content-Type: text/html

<html>...</html>

GET is a request method. 200 OK is an example status code meaning the request succeeded.

HTTP vs HTTPS

Remember: HTTPS is not a different way to find a website. DNS still performs domain-name lookup; HTTPS protects the web communication.
